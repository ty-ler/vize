# Same-owner editor and project API transport

The original Vben Actions law retains a maximum process tree of four. Its complete current-source metrics recorded three package-owned clients and six persistent native children, with no edit-time respawn. The observed PIDs identify physical children, but the archived metrics alone do not identify each API versus editor role. The old failed run and its whole artifact remain historical evidence.

The existing bridge worker can opt into opening its project-session API through that same client’s configured editor LSP attachment. The attachment belongs to exactly one workspace configuration and native owner. Its project snapshot and virtual editor mirror remain private to that client; independent package clients never borrow another client or attachment. Batch constructors and the existing direct public constructors retain their API-first behavior. Authored original-program diagnosing sessions retain their independent overlay authority.

The attachment uses the existing `EditorLspSession::spawn_with_config`, `attach_api`, and `ProjectSession::open` APIs. Unix runtimes with an async API and an existing configuration may use it; Windows, synchronous/fake API launchers, absent configurations, and unsupported native attachments retain the existing independent API/editor fallback. Startup fallback first reaps the failed editor owner and logs its failure. It does not silently turn a genuine independent API startup error into success.

A retiring attached project releases its active snapshot while the backend is alive, then shuts down the owning LSP process before its configured API reader is closed and joined. Immediate disk invalidation retains the snapshot through owner reaping and attachment joining, then drops it without contacting the stale backend; a stopped-owner native control preserves the existing immediate-discard boundary. A project/configuration transition reaps the previous owner before constructing its replacement; the new configured project is never installed in another owner. Disk invalidation retains lazy recreation, without a global process pool or eager backend in an idle package.
