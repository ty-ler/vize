# Complete Docs rendering with four workers

This is the opt-in worker experiment for [#6830](https://github.com/ubugeeei-prod/vize/issues/6830).
The normal renderer still defaults to two workers. Explicit one and two retain
their original scheduling. Only the exact additional value `4` is admitted;
three, malformed strings and larger counts remain refused.

The slice is a Draft child of the Linux native-fault evidence PR #8686. It does
not change that diagnostic, the existing Docs one/two benchmark, product CSS,
background motion or the normal Docs build/deployment campaigns.

## Capture and failure laws

- Preserve the existing producer and all 119 routes, 238 desktop/mobile jobs.
- Preserve every initial and light/dark capture, native locale case, source,
  Japanese font, link, rule packet, text layout and complete raw PNG tile.
- Keep the separate awaited scroll operation and position assertion before
  each screenshot. Preserve native negative controls and all original deadlines.
- Four real contexts must finish creation before any of those contexts begins
  cleanup. A worker retains its slot until context close finishes.
- Operation, close and combined failures cannot mint successful receipts.
  Later requested jobs still drain, and browser/server cleanup remains awaited.
- Retain actual browser-law campaign packets on Actions, including failures.

## Same-source hosted comparison

The manual-only `docs-workers` component delegates to a compact composite action.
It installs the same dependencies/fonts and builds native packages and Docs once,
then runs the complete renderer with two workers and four workers. Both arms use
capture timing observation and fresh separate directories. Neither filters routes
nor rebuilds between arms. Four still executes after a baseline render failure;
such a pair cannot qualify.

The observer authenticates the actual Actions checkout, clean tracked source,
built OG source manifest, complete physical Docs distribution, renderer sources,
installed Playwright libraries, Node/browser executable and all installed font
files before and after both arms. Substituted links and reused output directories
are refused. Both original commands must succeed.

Qualification requires every original boundary, completed capture operation,
actual achieved context overlap, manifest-ordered page outcome and raw file hash.
The complete packets must agree, including font usage and PNG bytes. Only the
owned ephemeral loopback origin in named URL fields is normalized; query, hash,
external URL and original raw HTML remain exact. Timing/interleaving metadata is
observed separately. No failed/missing packet or PNG mismatch is waived.

Always upload both complete campaigns, source identity, raw screenshots/HTML,
native controls, per-page/per-tile timings and the paired qualification result.
This includes successful and failed campaigns.

## Acceptance and remaining work

The bounded local real-browser law passed all original one/two runs plus four,
with identical complete receipts/tile hashes and preserved failed-page drain.
Authored whole-238 packet fixtures also exercise source, route, device, theme,
glyph provider, native-control, checkpoint, cleanup and raw-image refusals.
These results do not establish hosted full-campaign speed or public Docs quality.

The full same-source Actions pair, exact-source required checks, protected full
gates and actual merge remain required. Record their immutable source/run/artifact
identities and accepted arm walltimes here before reporting a performance result.
The renderer duration includes browser/server cleanup and receipt writing, but
excludes its own timing sidecar write and final process exit; compare actual arm
step walltime too, and do not call an unexplained remainder cleanup.

Four may contend on a shared browser compositor/GPU, PNG encoding/transfer, font
requests, disk or live snapshot memory. Ordered two-then-four may benefit from
warm caches. Report that ordered observation only; a broader causal claim needs
qualified reverse/repeated evidence. No historical 90-to-41-minute attribution,
aggregate CI speed claim or default-four rollout follows from this slice.
