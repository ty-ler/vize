# Use mold for native Linux builds

Issue: [#6830](https://github.com/ubugeeei-prod/vize/issues/6830).

All active Linux build, release and benchmark jobs use mold 3.0.0 through
the shared `setup-mold` action. The upstream installation action is pinned
to a commit and leaves the system linker untouched. A native GNU target
compiler wrapper selects mold explicitly, including when a caller supplies
`RUSTFLAGS`. This removes dependence on rustc's default linker and avoids
replacing benchmark or release code-generation flags.

The wrapper applies only to the runner's native Linux GNU target. Existing
musl cross compilation uses Zig and rust-lld; Windows, macOS and WebAssembly
retain their platform linkers. Production LTO, optimization levels and
codegen-unit counts are outside this change. The existing allocation
ownership replay keeps its original Wild binary because it verifies a
historical build envelope. The unused Wild HTTP recovery action and its
transport regression tests also remain historical evidence.

The `mold linker` workflow builds and runs ordinary and fat-LTO Rust binaries
on Linux x86-64 and ARM64, then requires `mold 3.0.0` in each ELF `.comment`
section. Extra caller `RUSTFLAGS` are present in both builds. This proves
linker selection and release-mode compatibility; it is not a measured
end-to-end build-time improvement.

The shared source CLI receipt records the installed mold binary, compiler
wrapper and caller flags. The original400 harness accepts the approved
linker migration only when all other parsed workflow fields are identical;
its original inputs remain checked. A pre-existing Clippy failure in the
configuration error-message test is repaired with the existing `cstr!`
macro while retaining the exact expected string.

Current workflow tests accept the approved linker setup while retaining
the recorded historical fixtures and hashes. Native smoke preserves all
six hosts and twelve fresh-install rows, and the two retained Star workflow
contracts still compare every other YAML field. Their named Rust pin and
parser-recovery trigger updates are accepted separately; changed commands,
conditions, benchmark flags and workload matrices remain failures.
